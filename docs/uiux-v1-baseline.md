## 目的

## 选择性采纳清单

| 部分 | 采纳 | 实现前必须调整 |
| --- | --- | --- |
| 公司列表 | 单列连续列表、整行链接、公司名与行业城市优先、评价数明确 | 保留键盘焦点；链接内不放按钮；搜索结果空态可清除条件 |
| 评分 | 无样本不造分、不展示固定星星、数字与样本数相邻 | V1 保持现有 10 分制，与分布和评分页一致；不直接采用 PR 的除以二显示方式 |
| 首页 | 缩短标题区、减少嵌套卡片、直接呈现公司 | 不把按评价数排序称为个性化推荐；如保留该排序，命名“评价最多”；新增公司排序使用明确时间语义 |
| 目录 | 搜索、城市、排序集中；结果数及时反馈 | 不无故删除原有推荐率排序；页面内有搜索时，避免再放第二个大搜索框 |
| 公司概览 | 紧凑身份区、真实评分、评价主栏、统计次栏、正确的概览选中态 | 不保留无行为的关注按钮；不叠加多个含义重复的评价筛选；次要 MBTI 信息不抢占主流程 |
| 状态反馈 | 列表形状骨架、失败重试、无评价状态 | API 失败不能以演示数据代替；保留用户已经输入的条件 |
| 视觉基础 | 白底、细边线、紧凑字号、统一控件、足够的点击区域 | 保留现有品牌色，紫色方案不自动成为新品牌；全局 CSS 变更需检查范围外页面与深色模式 |

## 三页职责与交互规则

1. 首页负责快速进入公司发现；公司目录负责完整搜索筛选；详情负责阅读评价并决定是否贡献。
2. 每个区域只有一个明确的主要操作：搜公司、查看公司、写评价。
3. 评价提交、账号访问、举报及有用投票继续使用现有真实流程。
4. 未实现的功能隐藏，或明确不可用；不放可点但无反馈的装饰按钮。
5. 键盘焦点可见，触控目标至少 44px；若使用 ARIA tabs，要完成方向键、焦点管理和面板关联，否则使用普通按钮组。
6. 375、390、768、1280、1440px 均不横向溢出；长公司名、零评价、请求失败必须验收。

## 可修改设计体系

实现时将颜色、字级、间距、圆角、控件高度集中为语义变量，避免散落页面。
优先复用 CompanyCard、CompanyRating、列表骨架、搜索输入和按钮；不建立第三套同义控件。
可修改分为三层：

- 设计层：Figma 或 Penpot 中调整布局、组件与交互原型。
- 代码层：真实 React 组件与样式变量；由 PR 管理修改。
- 验收层：组件样例、三页桌面/手机截图、交互回归测试。

截图只是历史记录，不是可编辑图层；现有 Next.js 应用也不是开箱即用的拖拽编辑器。
Figma Code Connect 用于映射设计组件与代码组件，不等于任意双向实时同步。
Storybook Controls 用于可视化调整组件暴露的参数，不等于整站自由布局编辑。
若引入 Builder 可视化编辑，要先限定可编辑组件/页面，不让编辑器直接控制账号、权限、评分或数据库逻辑。

推荐两人协作方式：Figma 设计和评审 → 标记 Ready for dev → 对应组件 PR → Preview 联合验收 → 合并发布。
设计和开发不按人固定分工，两人均可提出与实现变更；每个 PR 由另一人验收。

工具官方资料：

- Figma Code Connect：https://developers.figma.com/docs/code-connect/
- Storybook Controls：https://storybook.js.org/docs/essentials/controls
- Penpot：https://penpot.app/
- Builder Visual Editor：https://www.builder.io/c/docs/101-visual-editor

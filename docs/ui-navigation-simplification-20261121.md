# 在场导航精简（PR36 增补）

> 11 月 22 日用户确认公司归入社区，最新方案见 [公司属于社区](community-information-architecture-20261122.md)。下文三项导航是上一轮方案，已由两项导航替代；工作记录与内部研究边界保持不变。

## 用户界面

- 主导航仅保留「社区 / 公司 / 我的」。手机底栏同样三项。
- 评分不再占独立导航，保留公司页的多维评分、评价和问卷流程；评分表单高亮「公司」。
- Pulse 不再作为面向用户的名称或独立页面。「我的」中折叠展示「工作记录 · 打卡与周报」，主动展开才加载个人记录；匿名公司趋势为二级折叠内容。
- 旧 `/pulse` 链接在功能开启时以 307 转到 `/me#work-records`，自动展开记录。未登录时保留登录后返回地址。
- 功能关闭时仍为 404；个人记录接口的会话、同意授权、删除确认和公司样本阈值规则保持不变。

## 内部研究边界

- `/research`、详情页及 `/api/research` 系列公开请求统一 404；响应禁止缓存。
- 入口层和页面/API 处理函数均有守卫，不依赖隐藏导航或上线范围变量。
- 不把个人「我的」视为内部后台，不向普通登录用户开放研究数据库。
- 保留研究采集、发布算法、原有实现、数据文件和数据库；无迁移、删表或清空数据操作。
- 未来需要内部研究后台时，另行加入明确的服务端管理员授权，不用本次开关代替权限控制。

## 验证与发布

- 回归覆盖桌面/手机、深浅色三项导航、旧链接、登录返回、折叠懒加载、打卡提交与删除、公司评分、研究页面/API 404。
- staging 冒烟检查访问 `/me`，Worker 本地运行检查验证旧 Pulse 重定向及研究隔离。
- 沿用 PR36；代码合入不代表已发布，需当前提交的 CI、隔离预览和正式发布验收。

# 司南 Web Beta 发布与回滚手册

## 发布前门禁

1. 创建不可变的应用版本，记录 git commit SHA，并写入 `APP_RELEASE`。
2. 执行 `npm run audit:release`，确认生产依赖不存在 high/critical 漏洞；Expo SDK 大版本升级须独立迁移和原生回归，不能在发布当天强制升级。
3. 在 staging 配置 `DATABASE_URL`、`AUTH_SECRET`、`CRON_SECRET`、Resend、错误追踪、`NEXT_PUBLIC_APP_URL`、`SUPPORT_EMAIL`，并设置 `LAUNCH_SCOPE_ONLY=true`。
4. 执行 `npm run release:check-env --workspace=@sinan/web`。
5. 按 [数据库演练手册](launch-database-runbook.md)完成迁移、重复迁移、核心集成测试和恢复分支演练。
6. 验证 `/api/health/live` 返回 200；`/api/health/ready` 只有在完整运行配置有效且数据库可达时才返回 200。部署平台必须以 ready 而非 live 作为接流门禁。
7. 用测试邮箱完成邀请码注册、登录、工作邮箱发信、评价提交、后台审核、公司页公开展示和账号注销。
   评价的“匿名”只指公开展示身份；未登录请求必须返回 401，每个账号 24 小时最多提交 5 条评价。
   注销后应保留已审核公开内容但解除用户/匿名画像关联，清除工作邮箱与验证码，并删除私聊及个人 P2 内容。
8. 人工触发一个无敏感信息的测试异常，确认错误平台收到与 `APP_RELEASE` 一致的事件。
9. 确认拍卖、圈层和私聊页面/API 返回 404，核心 Beta 页面仍可访问。

只有 staging 全部通过后，才允许将同一应用构建提升到生产。生产数据库只执行已在 staging 验证过的前向迁移。

## 发布后观察

- 发布后 30 分钟持续观察 ready 健康检查、5xx、邮件失败率、数据库连接错误与评价提交失败。
- 任何健康检查连续 3 次失败、5xx 明显升高或核心写入失败，立即停止流量提升并进入回滚。
- 审核队列、举报队列和守门指标每天检查；申诉成功率破线时暂停拉新。

## 应用回滚

1. 冻结新部署和非必要写入，记录故障版本 `APP_RELEASE` 与开始时间。
2. 将流量切回最近一个通过发布门禁的不可变应用版本。
3. 验证 live、ready、登录、公司查询和评价读取。
4. 不对生产数据库执行向下迁移。若旧应用与新 schema 不兼容，使用预先验证的兼容版本或前向修复迁移。

## 数据库恢复

如出现数据损坏或不可逆迁移问题，按数据库演练手册从发布前快照/分支创建恢复分支，切换应用连接并核对关键表。禁止在故障现场手工删表“修复”。恢复完成后记录 RTO、数据损失窗口和抽样核对结果。

## 发布记录

每次发布需保存：应用版本、迁移版本、操作者、开始/结束时间、门禁结果、健康检查、邮件与错误追踪 smoke test、回滚目标版本。记录不得包含连接串、令牌、验证码或用户数据。

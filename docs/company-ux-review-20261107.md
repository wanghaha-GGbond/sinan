# 公司页面交互修复 · 2026-11-07

## 范围与基线

正式站检查基线为 `web-v0.0.8`（应用 SHA `8d78bf0`）；本批从 `main` 的 `b924ac9` 开始。这里记录的是待发布改动，不代表正式站已经更新。

保留朋友合入的页面结构、公司 Logo、多维评分、C-BTI、评价与 Pulse。本批不修改评分算法、数据模型、迁移、邮件、邀请码或生产密钥。

## 已修复的行为

| 问题 | 修复 |
| --- | --- |
| 概览、评价、评分、承诺页标题和导航不一致 | 共用公司页头，始终显示公司身份、Logo、评分和四个入口；手机四项等宽 |
| 承诺入口直接打开表单，没有公司上下文 | 先显示公司和公开记录，再按登录及验证状态提供操作 |
| 未登录或未验证用户填写后才被拒绝 | 填写前给登录/验证入口，保留对应公司和登录返回地址；服务端权限检查不变 |
| 承诺结果默认“未兑现” | 必须主动选择；成功响应必须包含待审核记录才显示成功 |
| 承诺接口失败被当作空列表 | 服务端返回 503/no-store，客户端区分加载、空列表、失败并提供重试 |
| 提交失败后的反馈不明确 | 表单内显示错误、保留输入，防重复点击，不伪造成功 |
| 搜索和筛选刷新后丢失 | 状态写入 URL，支持刷新和浏览器返回；同步更新受控控件，避免勾选回弹 |
| 空列表仍提供没有作用的清除按钮 | 有筛选才显示清除；真正空库与筛选无结果分别显示 |
| 长承诺文本可能撑破页面 | 限定网格列最小宽度，正文换行 |

- `npm run test:unit --workspace=@sinan/web`
- `npm run test:uiux --workspace=@sinan/web`
- 新增公司专项测试覆盖浅/深色、390/1280 宽度、四页切换、筛选往返、搜索错误恢复、认证前置提示、提交失败/待审核成功、长文本布局。
- 全站回归同时覆盖既有评分草稿、问卷、登录注册、Logo、Pulse 与首页导航。测试使用隔离夹具；夹具评分不是生产数据。
- CI 和受保护 Preview 通过后才能合并；正式发布需要单独验证 Cloudflare 构建与运行时。

## 后续范围

这不是“全部 UI 已达到生产级”的结论。仍需持续对真实数据下的公司长名称、资料缺失、空评分及不同内容密度做视觉检查；结合实际用户反馈继续整理公司首屏信息层级和评价填写步骤。本批不为填充页面而制造评分或公司统计。

本批无迁移，发布失败可恢复最近已验证的 `web-v0.0.8` 应用版本；不得回到不支持 Pulse 数据清理的更早认证版本。

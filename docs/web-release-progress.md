## 第一步：账号找回与认证加固（2026-10-03）

状态：本地代码与验收完成；尚未推送、部署或执行线上迁移。真实邮件接通待域名和发信账号确认。

已实现：

- 登录页增加“忘记密码”，新增 `/forgot-password`、`/reset-password` 页面。
- 新增 `/api/auth/forgot-password` 和 `/api/auth/reset-password`；既有 API 地址及登录响应格式保持不变。
- 256 位随机重置凭证，数据库只存摘要；15 分钟有效，每账号最多一个有效链接，领取新链接会替换旧链接。
- 链接凭证放在 URL fragment，页面读取后移除，不写入浏览器持久存储；修改密码只能使用 POST。
- 以数据库时间判断过期；改密、消费凭证、增加会话版本在同一事务完成。并发请求只能成功一次。
- 改密后所有旧 JWT/cookie 失效，用户需要正常登录；注销账号同时清除重置凭证。
- 注册、登录和找回使用 PostgreSQL 原子限流。登录同时限制可信代理 IP 和账号，找回同时限制 IP 和邮箱；数据库异常时返回不可用，不退化为无限制。
- 邮箱不存在、受限时统一返回条件式受理提示；账号查询和邮件发送在响应后执行。邮件配置关闭时直接返回 503，不显示“发送成功”。
- 新密码为 8–128 字符；登录兼容已有较长密码（最大 4096），不截断输入。
- 发信错误日志不记录邮箱、密码、凭证或供应商响应正文。

安全设计参考：[OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。

## 上线前必须完成

1. 确认拥有并能管理 DNS 的域名，验证发信域名及支持邮箱。不得继续把未确认可用的 `support@sinanapp.cn` 当正式客服入口。
2. 海外沿用已有 `resend` 适配器时，配置 `MAIL_PROVIDER=resend`、已验证的 `MAIL_FROM_DOMAIN` 和 secret `RESEND_API_KEY`；`NEXT_PUBLIC_APP_URL` 必须是实际 HTTPS 入口。密钥不写入仓库、镜像或聊天。
3. 确认 `AUTH_TRUSTED_IP_HEADER` 与平台一致：Cloudflare 默认 `cf-connecting-ip`，Vercel 设置 `x-vercel-forwarded-for`，Nginx 使用其覆盖的 `x-real-ip` 并禁止绕过代理直连。缺失时保守共用 unknown 桶，不接受任意 `X-Forwarded-For`。
4. 在隔离 Neon staging 备份/恢复点上验证迁移，再备份 Beta 数据库，先应用 `0021`，再部署应用。未经迁移的新应用会拒绝认证，不能跳过此顺序。
5. 验证 Worker `after()` 后台工作能完成真实重置邮件与改密通知，并监测 `password_reset_delivery_failed`、`password_reset_notice_failed` 和 `rate_limit_unavailable`。
6. 使用所有者授权的测试邮箱完成真实投递与点击闭环，验证登录、注销、异常与无效链接；不要对真实用户账号执行验收重置。
7. **首次实际改密后，不得回滚到不检查 session_version 的旧应用**，否则可能重新接受旧 JWT。回滚目标必须保留会话版本校验，或采用经过验证的全量会话吊销方案；数据库不向下迁移。

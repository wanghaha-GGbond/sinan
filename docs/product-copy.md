# 界面文案

- 页面标题直接命名内容：公司、搜索公司、公司研究、我的评价。
- 一个操作只保留一个明确名称：搜索、写评价、提交、重试。
- 不在标题下重复解释页面用途；能通过输入框、按钮、选中态和进度条表达的，不另写一段说明。
- 空状态说明缺什么，旁边提供下一步；不劝用户“帮助后来者”“看清方向”。
- 错误反馈说明问题和可用操作，不展示内部实现，例如 mock、兜底、正式版本规划。
- 评分方法、数据来源放进可展开区域；可信度、样本不足和示例数据标记仍在相关数据旁展示。
- 隐私确认、不可逆操作、填写要求和审核状态不能为了简洁而删除。法律文本与真实用户内容不按此规则批量改写。
- 不写尚未实现的奖励、验证能力或绝对保证；看起来是链接的文字必须可以点击。

## 产品范围

在保留匿名评价、公司评分、C-BTI、研究和 Pulse 的前提下，增加按公司的讨论社区：

- `/community`：公司目录、全部动态、关注的公司、我的发布。
- `/company/[id]/community`：公司论坛，与概览 / 评分 / 评价 / 承诺并列。
- `/community/[postId]`：帖子、回复、赞同、分享、举报、作者删除。
- 话题：提问、工作体验、面试交流、职业发展；最新发布 / 最多赞同。
- `/community?view=reviews`：保留原有评价讨论，旧 `/api/community` 契约不变。
- `/moderation/forum`：管理员 / 审核员处理待审帖子、回复和举报。

借鉴 Glassdoor 的公司视角和 LinkedIn 的动态流，但本期不是实名职场社交网络。不加入私聊、好友关系、招聘投递、媒体上传或 AI 自动审核。论坛赞同 / 回复不计入公司评分或 C-BTI，不生成虚构互动。

## 交互与安全边界

1. 未登录可浏览已公开帖子；发帖、回复、关注、赞同、举报需有效账号。
2. 新帖子 / 回复一律 `pending_review`，作者可查看自己的未公开内容，其他用户不可见。只有审核员可公开，服务端再次验证数据库角色。
3. 隐藏主帖后停止公开访问、回复和赞同；主帖未公开时不能公开回复，但可以拒绝 / 隐藏回复以处理举报。
4. 无数据库、限流不可用、API 失败均返回真实错误；不回退 mock 或显示假成功。分页失败保留已加载内容，提交失败保留正文。
5. 写入拒绝跨站 Origin、限制 JSON 实际字节数为 16 KiB，采用用户 + 可信 IP 的持久化限流。原生客户端可使用现有 Bearer JWT，不接受调用方提供作者或审核状态。
6. `requestId` + 唯一约束保证相同提交重试不重复创建。赞同 / 关注使用幂等 PUT；事务锁住活跃用户和目标帖子，与注销串行化。
7. 普通响应采用字段白名单，不返回邮箱、用户 ID、提交编号、内部作者关联。复用已有屏蔽作者规则，未登录 / 封禁 / 注销账号不能写入。
8. 注销清除关注和赞同、清除未公开投稿、解除公开内容作者关联、匿名化举报者。已公开内容可能保留；隐私政策已说明。作者删除内容会覆盖正文并停止公开，审核日志不保存原文快照。
9. 列表 / 详情使用身份隔离的 query key、退出即失效的缓存和 `private, no-store` 响应，避免串号显示私有内容。

## 数据与 API

新增迁移：`0025_company_forums.sql`，在全部当前迁移之后执行；只新增表 / 索引，不改写既有公司与评价数据。

| 表 | 用途 |
|---|---|
| `forum_posts` / `forum_replies` | 帖子、回复及审核状态；时间精度为毫秒，保证游标序列化不丢失精度 |
| `forum_votes` / `forum_follows` | 用户唯一的赞同与公司关注；互动数从真实记录计算 |
| `forum_reports` | 去重举报和处理状态 |
| `forum_moderation_events` | 审核 / 作者删除审计，不保存正文快照 |

| 路径 | 方法与用途 |
|---|---|
| `/api/forum/posts` | GET 筛选与游标分页；POST 提交待审帖 |
| `/api/forum/posts/[postId]` | GET 帖子与回复分页；DELETE 自己的帖子或 `replyId` 回复 |
| `/api/forum/posts/[postId]/replies` | POST 提交待审回复 |
| `/api/forum/posts/[postId]/useful` | PUT `{ useful: boolean }` |
| `/api/forum/posts/[postId]/report` | POST 举报，可选 `replyId` |
| `/api/forum/follows` | GET 自己的公司关注；PUT `{ companyId, following }` |
| `/api/moderation/forum` | GET 审核队列；PATCH 携带 `expectedStatus` 和原因的审核操作 |

列表每页 20 篇，回复每页 50 条；同时间戳以 UUID 打破并列。游标绑定公司、话题、动态范围与排序，不允许跨筛选复用。最多赞同排序是实时排序，翻页期间赞同数变化可能改变位置，前端去重；需要固定快照时另做快照游标。审核队列每类一次最多 20 项，处理后刷新继续取队首，不宣称展示全部待审数量。

- 单测：游标绑定、严格输入、缺库 / 未登录 / 跨站拒绝、请求体实际大小、反向代理 Origin。
- PostgreSQL 16：全部迁移 + 重复执行；真实事务、幂等提交、并发赞同、作者权限、审核冲突、隐藏父帖、屏蔽、分页并列和公司隐藏。
- UI：390 / 1280 px、明暗主题、筛选、失败重试、输入保留、分页保留、关注 / 赞同失败不显示成功，原评价讨论继续回归。

- 本地 release 使用生产构建；改密后的登录在真实浏览器验证 Secure + HttpOnly Cookie，不降低生产 Cookie 安全设置。
- Cloudflare：验证模式构建、Wrangler dry-run 和本机 workerd 启动 / 缺库失败保护，不上传代码、不调用生产服务。

UI fixture 用于视觉 / 错误场景，不作为真实数据验收的替代。真实数据库测试只运行在本机临时 PostgreSQL；真实邮件专项本次不启用。

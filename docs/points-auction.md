# 在场积分竞拍 v1

2026-11-23，所有者确认：站内任务/活动获取；不可购买、充值、转让、提现、兑换现金或作为捐款。此版不接区块链、支付通道或新付费服务。不能把已通过的免费报名验收当作积分竞拍验收。

## 产品规则

- 名称为「在场积分」，与旧页面的信誉/方向值分开计算，不迁移历史现金拍卖的分、元或金额。
- 已验证注册邮箱：可领取一次 20 积分；「今日来在场」每天 5 积分，以服务端北京时间日期为准。奖励规则存在服务端，客户端不能传奖励金额或日期。
- 管理员/审核员按已核实的活动参与情况核发 1–1000 积分，必须填写活动 UUID、参与者注册邮箱与依据。同一活动/同一人只发一次；改变已有奖励的内容会被拒绝。普通用户不能自行核发。不可把公司好评、投票或刷帖作为奖励条件。
- 每场积分竞拍 1 个名额，盲拍，最多 50 位参与者；嘉宾资料与授权继续由运营核验。组织者不能参与自己创建的活动。没有预置嘉宾或虚构活动。
- 出价立即冻结；加价必须严格增加，仅冻结差额。截止后、活动开始前由运营点击确认，系统按最高积分、有效出价时间、稳定 ID 顺序中选，不支持人工绕过排名。未中选积分退回；中选冻结转扣除。
- 未中选前撤回退回冻结并清除问题；中选后个人放弃不退积分。活动取消或下架退回冻结与已扣积分；操作前展示规则。
- 第一版确认中选仍由运营手动发起，不谎称有后台自动结拍任务。运营须在截止后、活动开始前处理；逾期请取消活动退回积分。
- 注销销毁本人账户、可用/冻结积分和个人流水，不转给他人；其他人的活动奖励记录解除注销操作者的关联。

## 数据与保护

迁移 `0027_points_auctions` 是增量迁移；保留现有免费报名与旧现金拍卖表。`point_accounts` 分开存可用/冻结数，`point_entries` 保存服务端操作键、增减与操作后余额；数据库约束禁止负值，账户总量上限 100 万。

Beta 使用事务级 advisory lock 统一积分写入和注销的锁顺序，再锁活动/账户；保证并发领取、跨场出价、结拍、退款与注销不能重复消费。首版因此偏向正确性而非高并发，每场最多 50 人；扩大规模前需要做吞吐与退款批处理优化。事务锁依据 [PostgreSQL 16 文档](https://www.postgresql.org/docs/16/explicit-locking.html#ADVISORY-LOCKS)。

公开活动不返回报名者身份、出价、余额、私密问题或安排。本人出价独立查询，不依赖“我的报名”前 20 条记录。余额、本人流水和报名禁止缓存；账户切换后不复用其他用户缓存。写入复用来源校验、请求体大小限制、身份/角色重查与持久化限流。重复请求不重复冻结；旧请求若已有后续修改返回冲突。失败保留表单，不显示假成功。

`biddingEnabled=false` 仍表示不提供历史现金竞拍；`pointsBiddingEnabled` 单独表示该场积分竞拍。所有 `paymentsEnabled` 仍为 false，`donationStatus` 为 `not_started`。

## 入口与开关

- `/me/points`：真实余额、任务领取、最近 30 条流水（不伪装为完整导出）。
- `/community/dialogues` 与详情：免费报名/积分竞拍共存。
- `/me/dialogues`：本人出价、冻结/扣除/退回状态、撤回。
- `/moderation/dialogues`：选择参与方式、最低积分、确认中选、取消与核发活动积分。

必须同时启用 `NEXT_PUBLIC_DIALOGUE_ENABLED=true`、`DIALOGUE_ENABLED=true`、`NEXT_PUBLIC_POINTS_ENABLED=true`、`POINTS_ENABLED=true`。默认关闭，独立运行时开关可紧急停止领取与新出价；取消退款和已有报名撤回仍可处理。不要关闭 `LAUNCH_SCOPE_ONLY`，历史现金拍卖、私聊等延后功能继续关闭。

Cloudflare 发布构建显式指定 `CF_DIALOGUE_ENABLED=true CF_POINTS_ENABLED=true`，由现有发布配置生成全部公开/服务端开关；不手改生成文件，不更改域名或访问保护。环境变量使用已有 [Workers vars 配置](https://developers.cloudflare.com/workers/configuration/environment-variables/)，不添加长期密钥。

## 发布门禁

先通过类型、lint、策略单测、数据库全量迁移/幂等、并发与对账测试、手机/深色 UI、真实隔离 Preview 的领取→出价→撤回→确认中选→取消退回→注销。仅在 exact commit 获 staging 审批后使用隔离库/密钥。上线前备份生产并先执行增量迁移，验证 Cloudflare 实际开关、接口和公开页面。当前文档不表示这些门禁已经全部通过。

上线产生积分记录后，不能回到不清理积分的旧注销代码；现有跨迁移回滚检查必须保留。首发异常优先关闭开关并前向修复，不 down migration。真实现金竞拍、支付、兑换、捐赠及嘉宾报酬另行评估、实现与验收，不因使用积分就宣称所有司法辖区合规。
